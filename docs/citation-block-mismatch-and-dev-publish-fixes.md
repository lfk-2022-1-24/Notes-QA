# 内网穿透发布 + 引用块错配（Sources）相关修复总结

## 背景

本轮主要解决两类线上体验问题：

- 通过内网穿透/公网域名访问时，开发模式（`npm run dev`）页面资源被拦截，导致上传等交互不可用。
- 问答结果中出现“答案内容正确，但引用块（Sources）不对应/不展示”的情况，尤其在 `八股.txt` 这类“编号题目 + 括号内直接给答案”的笔记结构中更常见。

## 1) 内网穿透发布后无法上传（dev 跨域资源被阻止）

### 现象

外部电脑通过穿透域名访问时，浏览器/服务端日志出现 Next.js dev 资源跨域阻止提示，页面脚本/样式加载不完整，表现为上传不可用或交互异常。

### 根因

Next.js 在开发模式默认**阻止外部域名**访问 dev 资源（`/_next/*`、HMR、字体等）。

### 改动

- 在 `next.config.ts` 增加 `allowedDevOrigins`，并支持用环境变量配置：
  - `NEXT_ALLOWED_DEV_ORIGINS=frp57.llt-service.cn`（多个域名可逗号分隔）
- `README.md` 补充了穿透场景下 dev 模式的说明，并推荐对外发布使用生产模式：`npm run build && npm run start`

### 验证方式

- 使用穿透域名访问时不再出现 “Blocked cross-origin request to Next.js dev resource …”。
- 上传能正常发起 `/api/notes/upload` 请求并完成导入。

## 2) “答案正确但引用块不对”：引用号错配（后端逻辑）

### 现象

回答文本中出现 `[n]`，但对应的 Sources 卡片/高亮块不是该问题的证据（甚至跳到完全不相关的内容）。

### 根因

后端曾对“模型输出了不存在的引用号”做了“就近映射/强行兜底”（例如只有 `[1]` 时把 `[3]` 改成 `[1]`），这会把引用号错误绑定到不相关来源上。

### 改动

- 在 `src/app/api/ask/route.ts` 中，引用号规范化改为**严格模式**：
  - 支持把 `［1］/【1】/[Source 1]` 统一规范为 `[1]`
  - 若引用号不在返回的 `sources.index` 集合中，则**直接丢弃**（不再映射到别的 source）

### 验证方式

- 返回的答案中不应出现指向不存在 source 的引用号。
- Sources 区域中 `[n]` 的内容应与答案引用一致。

## 3) “答案正确但引用块漂移”：编号题库（括号答案）高亮/片段提取不稳定

### 现象

例如问题“针对 NIO 的轮询产生了什么技术”，答案正确，但引用块可能落到同一份笔记里另一题（如“受检异常/非受检异常”）的片段。

### 根因

`八股.txt` 存在大量题目格式为：

- `18. 针对NIO的轮询 产生了什么技术（IO多路复用：...）`

该格式不一定包含 `?` 或 `问/答/解答:` 标记。旧的“编号 Q/A 片段提取”逻辑会把它当成“非 Q/A”跳过，导致 UI 引用片段漂移到同 chunk 内的其他题目。

### 改动

在 `src/app/api/ask/route.ts` 的 `refineRangeByNumberedQaQuestionText` 中：

- 将题目行的边界扩展为：遇到 `（`/`(` 视为“题目结束”（括号内通常就是答案）。
- 放宽 Q/A 判定：若题号附近存在“括号内答案”，且命中关键 token，即可判定为有效题目块参与定位与裁剪。

同时，为避免检索在短问题上“过滤过严导致退回到无关 chunk”，调整了检索后过滤策略：

- 允许 2 字中文 token（如“轮询”）参与强 token 过滤（避免把正确块过滤掉）
- `relaxedRelevant` 只要命中 1 个 token 就可以使用（避免命中不足 2 个 token 时退回到无关块）

### 验证方式

- 对 `八股.txt` 提问编号题目时，Sources 的摘录应落在对应题号附近，且高亮/跳转不会漂到同文件其他题目。

## 4) “没有引用块，只显示答案”：前端 Sources 展示兜底

### 现象

有时答案文本里缺少 `[n]`（模型忘写、或清洗后丢失），导致 Sources 区域为空，看起来像“没有引用块”。

### 根因

`src/components/ChatPanel.tsx` 原逻辑只显示“答案文本里出现过的引用号”对应的 Sources；如果答案没有任何引用号，即便后端返回了 `sources`，也不会展示。

### 改动

在 `src/components/ChatPanel.tsx` 增加兜底逻辑：

- 若 `sources` 非空但答案中解析不到任何引用号，则默认展示最相关的前 1–3 个 sources（仍可点击跳转高亮）

### 验证方式

- 即使答案文本意外未包含 `[n]`，也应能在 “Sources” 区域看到可点击来源卡片。

## 涉及文件清单

- `next.config.ts`：新增 `allowedDevOrigins`（通过 `NEXT_ALLOWED_DEV_ORIGINS` 配置）
- `README.md`：补充内网穿透 + dev 跨域说明与生产启动建议
- `src/app/api/ask/route.ts`：
  - 严格化引用号规范化（不再把无效引用号映射到其他 source）
  - 改善短问题 token 过滤策略，降低无关 chunk 进入 sources 的概率
  - 修复“编号题目 + 括号答案”格式下的题目块定位与 UI 引用片段裁剪
- `src/components/ChatPanel.tsx`：Sources 展示兜底（无引用号时也展示 top sources）
