# 会议记录 004：议题追问引用块混入无关内容修复总结

## 现象（用户反馈）

提问：

- `会议记录 004的服务等级协议制定`

系统能够给出正确答案，但引用块（sources）会混入无关内容，例如：

- 引用到 `# 会议记录 005` 的开头
- 引用到其它无关的“参会人”或行动项片段

## 根因

`meeting_会议记录.md` 是“多条会议记录拼在同一份 note（notes.content）”的结构，并且 chunks 的切分存在：

- **跨边界 chunk**：一个 chunk 可能同时覆盖“会议记录 004 的尾部 + 会议记录 005 的开头”
- **模板/行动项混入**：同一 section 内的“行动项汇总”等段落可能包含泛化词（如“性能基准测试”“方案文档”），容易被检索/选源误认为与目标议题相关

在这种结构下，如果直接把 chunk 当作 sources 返回，就可能把不属于“会议记录 004 / 议题1”的内容带进引用块。

## 修复策略（通用）

当问题满足“**会议记录 00X + 指定议题（agenda subtopic）**”时，改用“note 原文切片”生成引用块，而不是依赖 chunk 边界：

1. **精确切出会议记录 section**
   - 从 `notes.content` 定位 `# 会议记录 004` 的起点
   - 终点为下一条 `# 会议记录 YYY` 的起点（或文档末尾）

2. **精确切出目标议题 section**
   - 在上述会议记录 section 内，定位 `## 议题N: 服务等级协议(SLA)制定`
   - 截取到下一条 `## 议题...` 或 `## 行动项汇总`（或 section 末尾）

3. **只返回该议题 section 作为唯一引用块**
   - `sources` 收敛为 1 个，避免混入 `会议记录 005` 或其它无关块

该策略对其它议题（如 `API网关选型评估`、`代码审查规范强化` 等）同样适用。

## 验证结果（本地）

修复后本地测试 `会议记录 004的服务等级协议制定`：

- `sources` 由多个混杂块收敛为 **1 个**
- 引用块以 `## 议题1: 服务等级协议(SLA)制定` 开头，包含背景/讨论要点/决议
- 不再出现 `# 会议记录 005` 或其他无关引用块

## 相关实现位置

- 后端主逻辑：`src/app/api/ask/route.ts`
- 关键新增逻辑：
  - 基于 `notes.content` 的会议记录 section 边界计算
  - 从会议记录 section 内提取目标 `## 议题N:` 的精确切片并生成单一 source
