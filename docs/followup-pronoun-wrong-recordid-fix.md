# 跟进提问（指代词）误继承会议记录ID 修复总结

## 现象（用户反馈）

用户先问：

- `反射的优点`

系统能给出正确回答与引用块。

紧接着用户追问：

- `它的缺点`

系统却错误回答为某个会议记录（例如 `会议记录 025`）的基本信息/议题，并返回会议记录相关引用块，明显与“反射”的上下文不一致。

## 根因

系统为了支持“会议记录”场景的追问（例如 `会议记录 002` → `它的议题有哪些`），会在检测到指代词/跟进词（如 `它/其中/里面/这次/刚刚`）时，从历史对话中推断 `recordId`（会议记录编号）。

此前的实现会从 **历史任意一轮** 向后查找最近出现过的 `会议记录 0XX`，因此当更早的对话里出现过会议记录（例如 `会议记录 025`），就可能在用户问 `它的缺点` 时被误继承，导致检索与回答被强行“带偏”到会议记录内容。

## 修复策略

将“从历史继承会议记录 ID”的范围收紧为 **仅允许继承上一轮**：

- 只有当 **上一轮** 明确是会议记录相关问答（问/答中出现 `会议记录 0XX`），下一轮的指代词追问才会继承该 `recordId`
- 如果上一轮不是会议记录（例如讨论的是“反射”），即使本轮出现 `它/其/其中`，也不会去更早历史里捞会议记录编号

这样可以保证：

- `反射的优点` → `它的缺点`：跟随“反射”语境，不会跳到更早的会议记录
- `会议记录 025` → `它的议题有哪些`：仍能正确继承会议记录编号，保持会议记录追问体验

## 验证结果（本地）

本地以两轮对话回归：

- `反射的优点`：命中反射相关内容并返回正确引用块
- `它的缺点`：继续命中反射的缺点并返回对应引用块

未再复现“误回答为会议记录 025 基本信息/议题”的问题。
