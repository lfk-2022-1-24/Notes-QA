## 背景 / 现象

在提问 **“英语课就是背单词、学句子吗？”** 时，系统能给出正确答案，但点击溯源或在引用块预览中，引用片段会 **向上漂移**，把上一题答案的尾巴一起带进来，例如出现不相关的前缀：

- `马虎偷懒...数学教会我们严谨...`（上一题内容）
- 然后才是 `3. 问：英语课就是背单词、学句子吗？ 答：不是的！...`

这会造成“答案对，但引用块不够精准”的体验问题。

## 根因定位

该笔记来源为 `docx`（例如 `4-6年级知识库600题.docx`）。在 `docx` 抽取成纯文本后，多道题的内容常常会被 **扁平化拼接成一个长段落**（换行/段落边界弱或丢失），导致：

- 后端在生成 UI 引用片段时，如果仅使用“关键词命中 + 句子/段落裁剪”，命中点可能落在 **相邻题目**（上一题/下一题）的尾部；
- 因为边界不清晰，裁剪窗口会把“上一题的尾巴”一并包含，从而出现“往上漂移”。

本质上，这是 **编号 Q/A 结构（`N. 问：... 答：...`）的边界识别不够强**，而不是高亮渲染或前端滚动的问题。

## 修复方案

将 “PDF 专用的 Q/A 题干匹配裁剪” 泛化为 **所有格式通用的编号 Q/A 裁剪**，在生成 UI `sources` 时优先按题干定位到正确题号的块边界，而不是只靠 token 命中位置：

- 新增 `refineRangeByNumberedQaQuestionText()`：
  - 在 chunk 中扫描 `N. 问：` 的题号头（考虑解析器把换行扁平化，所以允许“非数字边界”，不依赖 `\n`）
  - 在每个题块中提取 `问：...` 的题干文本，按 **题干相似度 + token 命中** 选择最匹配块
  - 返回该题块的短片段（并做长度裁剪/trim）
- 在 UI `uiSources` 生成阶段，对每个 source **优先应用**该裁剪（不限 `.pdf`，`docx/txt/pdf` 都可命中）

涉及文件：

- `src/app/api/ask/route.ts`

## 验证结果

对问题 **“英语课就是背单词、学句子吗？”** 进行调用后，返回的引用块片段稳定为：

- `3. 问：英语课就是背单词、学句子吗？ 答：不是的！...`

且不再包含上一题的尾巴（如“马虎偷懒...”），引用块与答案内容一致，溯源更精准。
