## 问题现象

当提问 **“反射的优点有哪些？”** 时：

- **答案内容正确**（例如：优点是“灵活、解耦”）
- 但 **引用块内容不相关**，出现类似“非检查时异常 … FileNotFoundException / ClassNotFoundException …”这样的片段，导致溯源不可信。

## 复现与定位

命中的笔记为 `八股.txt`，该笔记中相关条目实际是：

- `12. 反射的优缺点（优点：灵活 解耦 缺点 性能开销 ...）`

它属于一种常见的“编号条目 + 括号内直接给结论”的格式，特点是：

- 有 `12.` 这种编号
- 但 **没有** `问：/答：/解答：` 这样的显式 Q/A 标记
- “优点/缺点”等信息在同一行括号里

此前引用片段裁剪主要依赖“关键词命中点”，在 `八股.txt` 这种扁平化文本中，命中点可能落在相邻条目（例如异常）附近，从而出现**引用块跑偏**。

## 根因

1. **编号块裁剪过于依赖 Q/A 标记**：缺少 `问/答/解答` 时，条目容易被当作普通列表而跳过，最终回退到不稳定的关键词裁剪。
2. **过滤 token 对 2 字关键词不友好**：像“反射”“优点”这种 2 字中文词，如果没有被强制纳入匹配 token，可能在过滤/排序阶段被弱化，导致错误块进入 `sources`。

## 修复方案

在 `src/app/api/ask/route.ts` 做了两项增强：

1. **增强编号条目识别**（`refineRangeByNumberedQaQuestionText`）  
   即使没有 `问/答/解答`，只要标题行看起来像“优缺点/区别/是什么…”这类条目，并且命中 **至少 2 个关键 token**（例如 `反射 + 优点`），也允许作为有效块并按题号边界裁剪。

2. **强制把聚焦 token 加入匹配集合**  
   对“topic + aspect（反射 + 优点）”这种问题，将 `focus.topic` / `focus.aspectWord`（即使是 2 字）强制加入过滤与裁剪 token，避免被“长度门槛/稀有度过滤”误伤。

## 验证结果

对 **“反射的优点有哪些？”** 重新请求后：

- 引用块稳定返回 `12. 反射的优缺点（优点：灵活 解耦 ...）`
- 不再引用到“非检查时异常 …”等无关片段
